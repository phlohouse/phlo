# Engineering map

Use this map to find the source that owns a change before editing. A nearby implementation is not necessarily the authority: metadata and generated copies often have a different owner.

| Task | Authoritative source | Code ownership | Focused checks | Generated or derived files |
| --- | --- | --- | --- | --- |
| Change core CLI, configuration, plugin contracts, or project generation | `src/phlo/`, root `pyproject.toml`, and focused tests under `tests/` | Core runtime in `src/phlo/`; cross-package contracts remain provider-neutral | Focused `pytest`; `make typecheck-python`; quickstart smoke for generated-project behaviour | Project `.phlo/` state is runtime output; test fixtures must be regenerated through the CLI |
| Change a provider or service package | Package `pyproject.toml`, source, service manifests, and tests | `packages/<package>/`; shared test helpers in `packages/phlo-testing/` | Package tests on the supported Python versions; relevant integration suite for service boundaries | Built wheels, Compose output, caches, and `*.egg-info` are derived |
| Change an integration across Iceberg, Dagster, API, or another service | Integration tests and the participating package contracts | `packages/*/tests` plus `.github/workflows/integration.yml` | The named integration test directory with `-m integration`; then the integration lane where practical | Container state and integration evidence are outputs, not source |
| Change Observatory Python service behaviour | `packages/phlo-observatory/pyproject.toml`, Python modules, manifests, and Python tests | `packages/phlo-observatory/src/phlo_observatory/*.py` | Observatory package tests; support-manifest validation when the exposed contract changes | Python build metadata and bundles are derived |
| Change Observatory routes, components, or server adapters | Inner `package.json`, `vite.config.ts`, `vitest.config.ts`, and frontend source | `packages/phlo-observatory/src/phlo_observatory/src/` | `npm test`, typecheck, lint, Prettier check, build, and browser inspection for visible changes | `src/routeTree.gen.ts` is generated from route files; npm owns `package-lock.json` |
| Change the Phlo agent | `apps/phlo-agent/package.json`, runtime source, and `agent/instructions.md` for behavioural policy | `apps/phlo-agent/agent/` | `npm test`, typecheck, and build; exercise affected live boundaries | npm owns `package-lock.json`; deployment output is derived |
| Change public documentation | Implemented code and configuration first; Markdown under `docs/` second | `docs/`; `pymdx.toml` controls site generation | Codespell and `make docs-build`; test every documented command that changed | `docs-site/` is generated by pymdx and is not documentation source |
| Change package versions or compatibility | Each distribution's `pyproject.toml` | Root and package metadata; release tooling in `scripts/` | `scripts/check_version_drift.py`, support validation, and package builds | Lockfiles are tool-generated; support and registry copies must agree with package metadata |
| Change plugin catalogue data | `registry/plugins.json` plus package entry points and metadata | Registry and the package providing the plugin | `python3 scripts/generate_plugin_registry_data.py --check`, version-drift check, and relevant discovery tests | Run `python3 scripts/generate_plugin_registry_data.py` to update `src/phlo/plugins/registry_data.json` |
| Change support status or support schema | `registry/support/v1.json` and `registry/support/schema/v1.json` | Support registry, evidence paths, package metadata | `python3 scripts/validate_support_manifest.py` and `python3 scripts/check_version_drift.py` | `src/phlo/support_data/v1.json` is the wheel copy; keep it byte-for-byte equal to the registry manifest |
| Change dependencies | The relevant `pyproject.toml` or `package.json` | Root, package, Observatory frontend, or agent app according to dependency use | Locked install, focused tests, dependency audit where risk changes | `uv.lock` and npm `package-lock.json` files are generated by their package managers |
| Change GitHub Actions or repository scripts | Workflow YAML and scripts under `.github/workflows/` and `scripts/` | CI, release, security, and maintenance automation | Focused script tests; YAML parse; `make zizmor`; `make actionlint` where Docker is available | CI artefacts and release evidence are outputs |

## Generated-file rule

Change the authority, run the owning generator or package manager, and review both the source and generated diff. If no generator is documented or discoverable, preserve the generated file and report the missing path instead of hand-editing an unexplained copy.
