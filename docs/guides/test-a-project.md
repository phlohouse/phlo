# Test a project

This guide adds a schema-focused pytest test, uses Phlo's testing helpers, and runs the CLI validation gates before a workflow reaches the stack.

## Before you start

- You have a project created with `phlo init`, with `tests/` and the CSV template files available.
- `phlo-testing` is installed from `packages/phlo-testing`, and the project environment includes pandas, Pandera, and pytest.
- You know the schema module generated by the template, usually `workflows/schemas/csv.py`.

## 1. Observe the fresh-template behaviour

Run the test gate before adding a test:

```bash
phlo test
```

A fresh template has no tests and `phlo test` prints `No tests were collected. Add tests under tests/ to enable this gate.` This is an intentional empty gate, not evidence that a project test passed.

## 2. Add a schema test

Create `tests/test_events.py` and validate a DataFrame against the CSV template schema:

```python
import pandas as pd

from workflows.schemas.csv import EventsSchema


def test_events_match_template_schema():
    frame = pd.DataFrame(
        {
            "event_id": ["1-2025-01-15", "2-2025-01-15"],
            "id": [1, 2],
            "name": ["alpha", "beta"],
            "value": [10, 20],
        }
    )

    validated = EventsSchema.validate(frame)

    assert list(validated["event_id"]) == ["1-2025-01-15", "2-2025-01-15"]
```

The test exercises the same Pandera model used by ingestion and fails with the column or constraint that no longer matches the template.

## 3. Use phlo-testing helpers when integration is needed

The `phlo_testing` package provides project and service fixtures rather than replacing pytest. Its public execution helpers include `test_asset_execution`, `test_asset_with_catalog`, `test_asset_with_trino`, `MockAssetContext`, and `TestAssetExecutor`.

```python
from phlo_testing import test_asset_execution
from workflows.ingestion.csv.events import csv_events


def test_asset_can_run():
    result = test_asset_execution(csv_events, partition="2025-01-15")
    assert result.success
```

The helper runs the selected asset through the testing execution path and returns a structured result. Use the fixture or harness that matches the test's required services.

## 4. Run focused tests

The test command supports local execution, coverage, verbosity, and pytest markers:

```bash
phlo test --local
phlo test -v
phlo test --coverage
phlo test -m integration
phlo test dlt_events
```

| Option | Effect |
| --- | --- |
| `--local` | Run without Docker. |
| `--coverage` | Generate a coverage report. |
| `-v, --verbose` | Show verbose pytest output. |
| `-m, --marker TEXT` | Select tests with a pytest marker. |
| `ASSET_NAME` | Limit collection to an asset-specific test target. |

## 5. Run static project gates

Validate schema syntax and workflow structure before using an integration test:

```bash
phlo validate-schema workflows/schemas/csv.py
phlo validate-workflow workflows/ingestion/csv/events.py
```

The schema gate reports syntax and integration issues, while the workflow gate checks the file path and discovered asset structure without requiring a full materialisation.

## Verify

```bash
phlo test events
```

The output collects `test_events_match_template_schema` and reports one passing test. The exact test count may include other project tests.
