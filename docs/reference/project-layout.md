# Project layout reference

## Generated project tree

The `minimal` template creates the base tree. Provider templates add their own files.

```text
project/
├── phlo.yaml
├── pyproject.toml
├── .env.example
├── .gitignore
├── README.md
├── workflows/
└── tests/
```

The `csv-batch` template adds:

```text
data/events.csv
workflows/ingestion/csv/events.py
workflows/schemas/csv.py
```

`phlo.yaml` contains project configuration. `pyproject.toml` declares project dependencies and test settings. `workflows/` contains discovered workflow modules. `tests/` contains project tests.

## Generated runtime state

`.phlo/` is generated by `phlo services init` and is local runtime state.

```text
.phlo/
├── docker-compose.yml
├── overrides/.env
├── secrets/.env
├── .gitignore
├── trino/
│   ├── jvm.config
│   ├── config.properties
│   ├── node.properties
│   └── catalog/
├── dagster/
│   ├── Dockerfile
│   ├── entrypoint.sh
│   ├── workspace.yaml
│   └── dagster.yaml
└── logs/
```

The exact service directories depend on installed service packages. `.phlo/secrets/.env` contains local secret values and should not be committed.

## Templates

| Name | Package | Generated content | Next step |
| --- | --- | --- | --- |
| `minimal` | `phlo` | Empty project tree. | `phlo test` |

| `dbt-medallion` | `phlo-dbt` | Bronze, silver, and gold dbt project. | `phlo test` |
| `observability-demo` | `phlo-dlt`, `phlo-pandera`, `phlo-otel` | Pipeline with telemetry wiring. | `phlo test` |
| `sling-replication` | `phlo-sling` | Sling replication project. | `phlo test` |

Template discovery uses the `phlo.project_templates` entry-point group. The list can vary with installed packages.
