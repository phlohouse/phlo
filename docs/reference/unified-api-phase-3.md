# Phase-3 `/api/v1` assets and overview slice

This is a partial backend delivery for [issue #1035, phase 3](https://github.com/phlohouse/phlo/issues/1035). It is not the Observatory UI wiring and does not claim phase-3 acceptance.

Every route requires an authenticated principal, an allow decision from the configured policy backend, and exactly one `env=prod|staging` selector. The server resolves that environment through `PHLO_V1_ENVIRONMENTS`; Dagster assets and checks are filtered by the mapped repository location before data is returned. The Nessie ref remains operator-controlled and is not accepted from callers. Authorization uses `asset.read` for asset, check, source, layer, and overview reads, and `run.read` for materialization history. Failures do not become empty asset lists.

## Routes

| Method and path | Evidence returned |
| --- | --- |
| `GET /api/v1/assets?env=...&limit=...&cursor=...` | Dagster asset key, description, compute kind, group, source flag, dependencies, and latest materialization timestamp/run ID. When the same key is defined in multiple locations and Dagster history cannot be disambiguated, `history_scoped` is false and history fields are null. Cursor is bounded to `env` and this list; limit is 1–500. |
| `GET /api/v1/assets/{asset_id}?env=...` | Asset definition, Dagster `TableSchemaMetadataEntry` columns, and typed column lineage, when present. `schema_observed_at` is set only when the latest materialization carries schema metadata; static definition metadata has no fabricated observation time. |
| `GET /api/v1/assets/{asset_id}/runs?env=...&limit=...` | Bounded asset materialization history (timestamp, run ID, step key), not a complete audit trail of Dagster runs. |
| `GET /api/v1/assets/{asset_id}/checks?env=...&limit=...` | Dagster check definitions scoped by asset key and repository location, plus typed recent evaluation metadata. Each execution's run is resolved and included only if its repository location matches the selected environment; runless evaluations are omitted because they lack location identity. Limit is 1–100. |
| `GET /api/v1/tables/{namespace.table}/snapshots?env=...&limit=...` | Ref-bound Iceberg snapshot history from the configured Nessie ref. Identifier syntax is restricted; output is limited to 500 records. |
| `GET /api/v1/tables/{namespace.table}/schema-history?env=...&limit=...` | Ref-bound retained Iceberg schema versions, IDs, field IDs/names/types/requiredness, and current schema ID. Iceberg does not expose observation timestamps through this metadata list, so none are added. |
| `GET /api/v1/assets/{asset_id}/materialization-estimate?env=...&partition_count=...` | Validates that the asset exists in the selected Dagster location and returns the requested partition count. Cost is explicitly `null` because no cost source exists; this is not a workload or duration estimate. |
| `GET /api/v1/sources?env=...&limit=...&cursor=...` | The same asset records filtered by Dagster's explicit `isSource` flag, before pagination. |
| `GET /api/v1/layers?env=...&limit=...&cursor=...` | Counts and latest materialization grouped by Dagster's real `groupName`; it does not assert that Dagster groups are governance/data layers. |
| `GET /api/v1/overview?env=...` | Asset and materialized-asset counts, latest materialization timestamp, phase-2 incident counts, SLA-backed freshness counts, and Dagster run status counts from up to 100 recent runs filtered by the configured location. `run_history_truncated` signals a full 100-row result. Audit counts are null because there is no configured aggregate audit source. |

Asset definitions, materialization evidence, and column-lineage metadata come from Dagster GraphQL. Snapshot/schema history loads Iceberg metadata using the operator-mapped Nessie ref. Incident counts and explicit freshness SLA overrides come from the phase-2 durable incident store. Dagster outages, malformed responses, and incident-store outages fail the overview instead of returning synthetic zeroes.

## Not implemented; source boundary

- **Ref-aware bounded data preview:** not exposed. `PyIceberg TableScan.limit()` bounds returned rows only; it does not bound manifest planning, bytes/files read, or execution time. Trino ref selection is per catalog (`iceberg`, `iceberg_dev`, and WAP-owned `pipeline-run-*` catalogs), not per request/session; `for_ref` only provisions WAP-owned run refs. Its `SELECT ... LIMIT` caps output, HTTP timeout does not cancel a running query, and no server scan-byte/time limits are configured. Do not pass a Nessie ref as a Trino schema or claim either adapter is safely bounded. A viable follow-up is a pre-provisioned operator allowlist of per-ref query catalogs plus Trino server resource groups/scan limits and query-ID cancellation on deadline; otherwise use a worker with hard termination and enforced scan preflight.
- **Latest/backfill/full actions:** not exposed. Existing Dagster helpers can target a repository location, but there is no API-side contract proving that the selected location executes against the mapped Nessie ref. A safe adapter must validate the location/ref pair at launch and reject a mismatch before run creation. It must also use #989's shared idempotency, rate-limit, and operation-exclusion store, or remain explicitly single-replica. The current phase-2 local operation journal does not establish that production guarantee.
- **Audit creation and aggregate audit evidence:** not exposed. The core `PostgresAuditStore` exists, but no configured API emitter/store owner is wired; constructing the store runs `CREATE TABLE IF NOT EXISTS`. The local operation JSONL writer is not the compliance audit chain. Until its owner/configuration is established (without an implicit schema change), no durable audit creation or audit count is claimed. Check history is implemented from Dagster's `assetChecksOrError` and `assetCheckExecutions`, location-scoped via each execution's run origin.
- **Run history, usage, and overview evidence:** `/assets/{asset_id}/runs` is materialization history only. `/overview` includes location-filtered status counts for up to 100 recent Dagster runs, but not full asset-associated run history. No environment/ref-scoped usage authority has been wired; audit counts remain null.
- **Schema/snapshot history:** implemented through ref-bound Iceberg metadata. Iceberg snapshots and retained schema metadata are not Dagster audit/check outcomes and are reported separately.
- **Phase-3 UI:** Observatory client wiring remains separate.

No migration or shared/production write is part of this change.
