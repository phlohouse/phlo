# Phase-3 `/api/v1` assets and overview slice

This is a partial backend delivery for [issue #1035, phase 3](https://github.com/phlohouse/phlo/issues/1035). It is not the Observatory UI wiring and does not claim phase-3 acceptance.

Every route requires an authenticated principal, an allow decision from the configured policy backend, and exactly one `env=prod|staging` selector. The server resolves that environment through `PHLO_V1_ENVIRONMENTS`; Dagster assets and checks are filtered by the mapped repository location before data is returned. The Nessie ref remains operator-controlled and is not accepted from callers. Authorization uses `asset.read` for asset, check, source, layer, and overview reads, and `run.read` for materialization history. Failures do not become empty asset lists.

## Routes

| Method and path | Evidence returned |
| --- | --- |
| `GET /api/v1/assets?env=...&limit=...&cursor=...` | Dagster asset key, description, compute kind, group, source flag, dependencies, and latest materialization timestamp/run ID. When the same key is defined in multiple locations and Dagster history cannot be disambiguated, `history_scoped` is false and history fields are null. Cursor is bounded to `env` and this list; limit is 1–500. |
| `GET /api/v1/assets/{asset_id}?env=...` | Asset definition, Dagster `TableSchemaMetadataEntry` columns, and typed column lineage, when present. `schema_observed_at` is set only when the latest materialization carries schema metadata; static definition metadata has no fabricated observation time. |
| `GET /api/v1/assets/{asset_id}/runs?env=...&limit=...` | Bounded asset materialization history (timestamp, run ID, step key), not a complete audit trail of Dagster runs. |
| `GET /api/v1/assets/{asset_id}/checks?env=...&limit=...` | Dagster check definitions scoped by asset key and repository location, plus typed recent evaluation metadata. Each execution's run is resolved and included only if its repository location matches the selected environment; runless evaluations are omitted because they lack location identity. Limit is 1–100. |
| `GET /api/v1/tables/{namespace.table}/snapshots?env=...&limit=...` | Ref-bound Iceberg snapshot history from the configured Nessie ref. Identifier syntax is restricted; output is limited to 500 records. |
| `GET /api/v1/tables/{namespace.table}/schema-history?env=...&limit=...` | Ref-bound retained Iceberg schema versions, IDs, field IDs/names/types/requiredness, and current schema ID. Iceberg does not expose observation timestamps through this metadata list, so none are added. |
| `GET /api/v1/assets/{asset_id}/preview?env=...&limit=...` | Runs a read-only Trino preview through a catalog mapped to the exact selected environment/ref. Rows are capped at 100, result pages at 8 MiB, serialized response at 1 MiB, runtime at 20 seconds, planning at 5 seconds, and requested physical scan at 256 MiB. The active Trino `nextUri` is deleted on output overflow, timeout, or client disconnect when available. Duplicate Dagster asset keys across locations are refused. |
| `GET /api/v1/assets/{asset_id}/materialization-estimate?env=...&partition_count=...` | Validates that the asset exists in the selected Dagster location and returns the requested partition count. Cost, scanned bytes, and duration are explicitly `null` with unavailable status fields because no estimate source exists; this is not a workload estimate. |
| `POST /api/v1/assets/{asset_id}/materialize?env=...` | Guarded Dagster materialization request. Defaults to dry-run, requires an idempotency key, pins the mapped repository location/name and Nessie ref tag, and appends API operation audit evidence. Live launch requires the single-replica and ref-tag-contract operator gates. |
| `POST /api/v1/assets/{asset_id}/backfill?env=...` | Guarded Dagster backfill for explicit caller-supplied partition keys (1–500), with the same idempotency, audit, location/ref pinning, and operator gates. |
| `GET /api/v1/sources?env=...&limit=...&cursor=...` | The same asset records filtered by Dagster's explicit `isSource` flag, before pagination. |
| `GET /api/v1/layers?env=...&limit=...&cursor=...` | Counts and latest materialization grouped by Dagster's real `groupName`; it does not assert that Dagster groups are governance/data layers. |
| `GET /api/v1/overview?env=...` | Asset and materialized-asset counts, latest materialization timestamp, phase-2 incident counts, SLA-backed freshness counts, and Dagster run status counts from up to 100 recent runs filtered by the configured location. `run_history_truncated` signals a full 100-row result. Audit counts are null because there is no configured aggregate audit source. |

Asset definitions, materialization evidence, and column-lineage metadata come from Dagster GraphQL. Snapshot/schema history loads Iceberg metadata using the operator-mapped Nessie ref. Incident counts and explicit freshness SLA overrides come from the phase-2 durable incident store. Dagster outages, malformed responses, and incident-store outages fail the overview instead of returning synthetic zeroes.

## Configuration and limits

- Preview is **fail-closed** unless all operator settings are present: `PHLO_V1_PREVIEW_SERVER_LIMITS_CONFIGURED=1`, `PHLO_V1_PREVIEW_TRINO_USER` naming a dedicated read-only Trino user, and `PHLO_V1_PREVIEW_CATALOGS` as JSON mapping exactly `prod` and `staging` to distinct catalog names and their exact `nessie_ref`. Each Trino catalog must be pre-provisioned with the intended Nessie REST ref. The server must enforce a resource-group/concurrency ceiling for that user and permit only the bounded query session properties used by the API. A boolean alone does not prove that cluster policy; the operator must verify the Trino configuration before setting it. API admission is two queries per process, so the Trino resource group is also required for a global cap across replicas.
- Trino's query physical-scan budget is an operational limit on bytes Trino accounts as scanned, not a strict ceiling on object-store traffic or manifest-planning bytes. The API refuses caller SQL, pins catalog in `X-Trino-Catalog`, selects only the mapped relation, and uses typed identifier quoting. It does not use PyIceberg row-limited scans or the legacy Trino preview route.
- Live asset actions fail closed unless `PHLO_V1_ACTIONS_SINGLE_REPLICA=1`, `PHLO_V1_ACTIONS_SINGLE_PROCESS=1`, and `PHLO_V1_ACTIONS_REF_TAG_CONTRACT=1` are set after deployment verification. These are operator assertions: deploy one API replica with one worker process, keep its `.phlo/state` idempotency journal and `.phlo/audit` log on the project-owned persistent volume, and ensure the mapped Dagster locations honor the `environment` and `phlo/ref` run tags. The code never auto-enables these gates.

## Not implemented; source boundary

- **Latest/full partition selection:** not exposed. The existing partition listing call returns the full key set without a pagination/bound contract, so it cannot safely resolve “latest” or prove that a bounded request covers every partition. Current backfill accepts explicit keys only (up to 500); this does not claim full-history coverage. A Dagster-owned bounded/paginated partition contract is needed for safe latest/full semantics. No live Dagster action was invoked.
- **Executable audit/check creation:** not exposed. `AssetCheckSpec` plus project-authored Pandera/decorator check code is discovered and adapted by `phlo_dagster/framework/discovery.py` at code-location reload. Current `/api/authoring/workflows` writes scaffolds and validate is separate; no operation validates, reviews, commits, and reloads a new executable check. A runtime-only mutation would disappear at reload. A narrow declarative authoring + explicit review + commit + reload workflow is required from the code owner; a P-only audit row is not an executable check. Aggregate overview audit evidence is also unavailable: the local operation JSONL writer is not the compliance audit chain, and no configured API audit emitter/store owner is wired (the existing `PostgresAuditStore` constructor performs `CREATE TABLE IF NOT EXISTS`).
- **Run history, usage, and overview evidence:** `/assets/{asset_id}/runs` is materialization history only. `/overview` includes location-filtered status counts for up to 100 recent Dagster runs, but not full asset-associated run history. No environment/ref-scoped usage authority has been wired; audit counts remain null.
- **Schema/snapshot history:** implemented through ref-bound Iceberg metadata. Iceberg snapshots and retained schema metadata are not Dagster audit/check outcomes and are reported separately.
- **Phase-3 UI:** Observatory client wiring remains separate.

No migration or shared/production write is part of this change.
